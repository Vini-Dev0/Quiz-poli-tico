# Internacionalização

O projeto continua em HTML/CSS/JavaScript e Express. Uma configuração compartilhada define os idiomas; recursos JSON previamente traduzidos são usados no servidor e no navegador. Não há serviço de tradução externa, React, migração de banco ou mudança nos pesos do quiz.

| Recurso / HTML lang | Prefixo | hreflang |
| --- | --- | --- |
| `pt-BR` | `/pt-br/` | `pt-BR` |
| `en` | `/en/` | `en` |
| `es` | `/es/` | `es` |
| `zh-CN` | `/zh-cn/` | `zh-Hans` |

## URLs e preferência

As mesmas páginas existem nos quatro prefixos: início, `/quiz`, `/metodologia`, `/sobre`, `/privacidade`, `/perguntas-frequentes`, `/resultado/:uuid` e `/admin`/`admin/login`. Os slugs internos permanecem iguais para manter a equivalência. Por exemplo, `/en/metodologia` é a metodologia em inglês. `/api/*`, assets, `/robots.txt` e `/sitemap.xml` não ganham prefixo.

O prefixo válido sempre determina o idioma. Na raiz `/`, o servidor entrega uma seleção acessível com links para todos os idiomas; JavaScript encaminha para a preferência manual salva, depois `navigator.languages`, depois português. Sem JavaScript, a seleção continua funcional. Não usamos IP ou geolocalização. A preferência fica em `localStorage` (`prisma.language`) e em um cookie funcional (`prisma_language`) para redirecionamentos antigos. Falhas de armazenamento não impedem navegar ou trocar de idioma.

Variantes portuguesas, inglesas e espanholas correspondem ao idioma disponível. `zh`, `zh-CN`, `zh-SG` e `zh-Hans` correspondem ao chinês simplificado. Variantes tradicionais como `zh-TW`, `zh-HK` e `zh-Hant` não são tratadas como simplificado: tentamos o próximo idioma preferido e, se nenhum for suportado, português. A seleção manual de 简体中文 continua disponível.

URLs antigas, como `/metodologia` ou `/resultado/:uuid`, respondem com redirecionamento temporário para a versão escolhida no cookie ou em `Accept-Language`. Parâmetros são preservados. `/en` normaliza para `/en/`; páginas internas normalizam a barra final. Fragmentos são preservados pelo navegador. O seletor mantém rota, query e fragmento, atualiza a URL e os metadados sem recarregar toda a aplicação. Respostas, token, pergunta atual, filtros e paginação continuam em memória. Atualizar a página do quiz retoma o snapshot da aba.

## Recursos e manutenção

- `frontend/js/i18n-config.js`: idiomas, correspondência, URLs, interpolação e fallback.
- `frontend/locales/<idioma>/ui.json`: textos e atributos dos templates (`data-i18n`, `data-i18n-aria-label`, etc.).
- `quiz.json`: 40 perguntas por ID, tópicos, escala de respostas e progresso.
- `results.json`: categorias, interpretação dos valores, gráficos e compartilhamento.
- `messages.json`: validação, erros, notificações e estados administrativos.
- `pages.json`: títulos, descrições, FAQ e páginas editoriais.
- `backend/src/services/i18n.js`: renderização, tradução da API e rótulos salvos.
- `backend/src/routes/pages.js`: páginas localizadas com SSR.
- `frontend/js/i18n.js`: carregamento inicial e troca de idioma sem reiniciar o quiz.

Todos os JSONs são UTF-8. Use chaves idênticas nos quatro idiomas e preserve parâmetros como `{score}`, `{minutes}` e `{page}`. Textos comuns usam `textContent` e o servidor escapa HTML. Não inclua HTML arbitrário nas traduções. O conteúdo editorial aceita somente links internos conhecidos pelo renderizador (`[[/metodologia|texto]]`). O servidor inclui no HTML os recursos necessários ao frontend; o conteúdo editorial fica no HTML renderizado, sem duplicar seu JSON no carregamento inicial. Chaves ausentes usam português; os testes recusam recursos incompletos.

### Nova pergunta

Traduza o mesmo ID nos quatro `quiz.json`. Regras numéricas e versão estão em `backend/src/data/questions.js`: não renumere perguntas publicadas, nem mude direção/peso para traduzir. Os textos portugueses desse arquivo vêm do recurso centralizado. Acrescentar ou alterar o questionário em si exige revisar a versão e os contratos de 40 perguntas; é uma alteração de produto distinta da tradução.

### Nova página ou texto

Adicione a mesma chave aos recursos, marque o nó/atributo no template e use `t('namespace.chave', parâmetros)` nos textos dinâmicos. Para página editorial, adicione sua definição em `backend/src/data/site-pages.js` e o conteúdo nos quatro `pages.json`. A definição alimenta rotas e sitemap. Atualize as expectativas de quantidade nos testes e no auditor de SEO ao acrescentar páginas.

### Novo idioma

Cadastre código, prefixo, nome nativo, hreflang e locale Open Graph em `i18n-config.js`; crie os cinco JSONs completos; amplie a correspondência de variantes quando necessário. Gere seu PNG social com `npm run assets:build` (requer Chromium de desenvolvimento). Atualize testes de idioma, quantidades de URLs e previews. Os componentes consomem o registro compartilhado, sem duplicar pontuação ou aplicações.

## API, dados e acessibilidade

O frontend envia `X-Language` nas chamadas existentes. A API traduz catálogo, erros, classificações e distribuições, adicionando chaves estáveis (`labelKeys`/`labelKey`) para reapresentação. Erros incluem `code` e `error`. Clientes antigos sem o header continuam com português e o contrato de URL de resultado sem prefixo; essa URL permanece funcional via redirecionamento.

IDs das perguntas e respostas 1–5 não mudam. Scores são calculados uma única vez no backend. Rótulos portugueses já persistidos permanecem no banco e são associados às chaves de tradução na apresentação; idioma não cria nova sessão nem recalcula resultado. Nenhuma migration nova é necessária.

O documento atualiza `lang`. O seletor usa `details`, links com nomes nativos, indicação do idioma atual e anúncio acessível; ao trocar, o foco volta ao seletor. Números e datas usam `Intl` no idioma ativo. Fontes do sistema incluem alternativas chinesas. Resultados compartilhados e cartões baixados mantêm o idioma atual.

## SEO e hospedagem

As 20 URLs editoriais (cinco páginas × quatro idiomas) têm conteúdo e metadados renderizados pelo Express antes de JavaScript, canonical próprio no domínio `SEO_URL`, Open Graph/Twitter localizados e hreflang recíproco, incluindo `zh-Hans` e `x-default`. O sitemap inclui as 20 URLs e suas relações multilíngues. Resultados, quiz em andamento e administração mantêm `noindex` e ficam fora do sitemap. A raiz é o seletor `x-default` da página inicial.

**Não é necessário alterar DNS nem adicionar variáveis.** `APP_URL` e `SEO_URL` continuam sendo origens sem prefixo de idioma. No EasyPanel, faça novo build/deploy usando o Dockerfile da raiz, Build Path `/`, porta 3000; encaminhe todos os caminhos ao Express. Não use fallback de SPA estática ou regras que removam os prefixos. Se houver CDN, não armazene redirecionamentos antigos que variam por Cookie/Accept-Language nem páginas administrativas/resultados; respeite os headers de cache. Configure HTTPS, `SEO_INDEXING_ENABLED=true` e `TRUST_PROXY` conforme a cadeia real de proxies, como antes.

Envie o mesmo `/sitemap.xml` ao Search Console. Inspecione URLs de cada idioma e verifique canonical e alternates no código-fonte. O comando `npm run seo:check -- https://ladopolitico.online` verifica a resposta pública; não comprova acesso do Googlebot real nem garante indexação ou posição nas buscas. Não é necessário pedir indexação do XML como uma página de conteúdo.

## Verificação

Na pasta `backend`, com dependências de desenvolvimento instaladas:

```sh
npm ci
npm run lint
npm run typecheck
npm test
npm run test:i18n
npm run build
```

`typecheck` verifica estritamente o módulo JavaScript compartilhado de configuração (JSDoc). Não representa conversão ou checagem TypeScript de todo o projeto. `build` gera Prisma e executa lint, essa checagem e os testes de i18n; o frontend não precisa de bundler. O build de produção real é o Dockerfile:

```sh
npm run test:docker
```

Integração e navegador precisam de PostgreSQL real e schema dedicado. Nunca execute contra produção. Exemplo para o banco de desenvolvimento local:

```sh
export TEST_DATABASE_URL='postgresql://quiz:quiz_local_only@localhost:5432/quiz?schema=quiz_test'
DATABASE_URL="$TEST_DATABASE_URL" npx prisma migrate deploy
npm run test:integration
npx playwright install chromium
npm run test:e2e
```

Execute as duas suítes sequencialmente: ambas limpam `quiz_test`. Testamos detecção e storage indisponível, acesso direto sem JavaScript, refresh, redirecionamentos, rota/query/fragmento, troca sem reload, 40 respostas, pontuação equivalente, progresso preservado, resultados e compartilhamento, login/filtros/paginação, traduções completas/interpolação e SEO multilíngue. As capturas móveis ficam em `test-results`, ignorado pelo Git.

As traduções preservam as proposições originais, inclusive afirmações potencialmente ambíguas (como liderança com amplos poderes na pergunta 34). O questionário permanece exploratório e sem validação psicométrica; os testes comprovam equivalência numérica, não validação científica entre culturas. Revisão editorial por falantes nativos é recomendada para futuras mudanças de conteúdo.
